# maTumbo Reality Integration .26

This document is the branch-level contract between the Reality Lattice substrate and the maTumbo Living Reality workspace.

## Core ontology

Reality is a programmable world. The lattice is the relationship layer between worlds.

Each RealityState carries identity, lineage, laws, dimensions, time, entropy, information, entities, causal history and metadata.

The workspace sits above that state and turns capabilities into navigable surfaces. A contract can live in a reality. A room belongs to a reality. A profile has an embodiment. A block can move between rooms. A ledger records actions. Prime Link explains their relationships.

## Contracts

Starter contract fixtures cover soccer, basketball, baseball, football and a product/release gate. They are local deterministic rehearsals using simulated TUMBO points.

Lifecycle:

draft -> open -> locked -> graded -> settled -> claimed

Void is permitted before grading. Grading records a deterministic digest. The branch explicitly marks realMoney=false, custody=false, wagering=false and settlement=false.

## Identity

The profile starts as a floorless maTumbo identity with the Obsidian outfit and queen-king embodiment. Available chess roles are pawn, knight, bishop, rook and queen-king.

Wardrobe starter states are Obsidian, Ivory / Gold, Explorer and Research.

## Reality Lens Omega

Reality Lens is semantic zoom: the same world can be inspected at system, room, object and interaction scale.

Current state records:

camera OFF by default
explicit local device activation
two-hand VIDEO interaction model
air keyboard
finger navigation

The branch stores the interaction contract. It does not claim that browser camera permissions or hand tracking are physically active until a client adapter is connected.

## Prime Chain / Link

Prime Chain is a software fabric, not a real blockchain.

Model:

world -> event -> contract -> action -> receipt -> lineage

Named principles in the current workspace are dark-matter analogy, entropy accounting, event-horizon boundary and information conservation. These are software design concepts in this branch.

## Commerce

t402 / PAYCORE is represented as a payment-required rehearsal rail:

resource -> payment required -> simulated receipt

No wallet, signing, custody, real settlement or monetary transfer is performed.

## Physics bridge

The workspace reuses the same PhysicsRuleSet and RealityLatticeEngine as the experimental physics substrate.

Supported world families include observed, quantum-branching, CPT mirror, antimatter, alternate history, active research, higher-dimensional and custom-law worlds.

Physics provenance remains explicit:

A = established or grounded-inspired
B = theoretical or interpretive
C = active research
D = speculative
E = software-created

Speculative models are executable when they have coherent state, rules, transitions and projections. Their software execution is not presented as evidence that the underlying physics is physically true.

## Rendering

The current Three.js projection still renders worlds, relationships and a selected-world Reality Lens. The DOM workspace supplies navigation, contracts, rooms, identity, ledger, companion and system controls.

This split is intentional: new clients such as VR, AR glasses, hand input or other semantic lenses can become additional projection and input layers without replacing the underlying reality model.
